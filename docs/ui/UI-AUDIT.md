# UI/UX audit of the Next.js web app (input to the Blazor port)

> **Historical.** This is the audit of the retired Next.js app; its findings drove the Blazor port. The current audit of `src/Gabinety.Web` and the task plan are in [`UX-PLAN.md`](UX-PLAN.md). The screenshots in `docs/ui/audit/` were regenerated from the Blazor host on 2026-11-22 (UX-003), so the file names and "Evidence" paths below now point at the new captures, not at the ones the text describes.

Date of the run: 2026-11-22. Target: `web/` (Next.js) as served by the fake profile (`dotnet run --project src/Gabinety.AppHost --launch-profile fake`).
Companion documents: [`DESIGN-CONTRACT.md`](DESIGN-CONTRACT.md) (what the port implements), [`tokens.css`](tokens.css) (the token block).
Nothing in `web/` was changed: the app is replaced, so this is a list of what to **not** carry over and what to fix on the way.

| `main` with under 150 characters of text | 24 visits: `/konto` (error only), 404 pages, `/logowanie`, `/moje/opinie` (see below) |
| Console | on every page "Applying inline style violates the following Content Security Policy directive" (the fake profile runs `next dev`; not verified against a production build, see 7) |

So the app is **not broken at the CSS level** (no overflow, contrast passes): the weakness is structural. It has one centred column and a link-and-underline vocabulary,
no real header, no signed-in state, no visual hierarchy between primary and secondary information, no dark theme, tiny touch targets, and a set of data and copy bugs that
make it look unfinished. The owner's "misaligned" feeling is mostly the missing spacing between inline elements (tabs glued together, counters far from their input,
buttons glued to the paragraph above) which no automatic check measures, so each is listed below with the screenshot.

Severity: **Blocker** = broken or unusable for a task; **Major** = hurts the product's credibility or conversion, or a clear usability failure; **Minor** = polish.
IDs are used by the contract (`DESIGN-CONTRACT.md`) and the task list.

## 2. Top 10 (what to fix first)

1. **G-1 Blocker** The header ignores the session: a signed-in user still sees "Zaloguj się / Załóż konto", and nothing anywhere links to *Moje rezerwacje*, *Konto*, *Panel programisty*, *Administracja* or *Wyloguj*. The confirmation page ends with "Wróć do wyszukiwarki".
2. **F-02 Blocker** `/konto` shows only "Dane konta są chwilowo niedostępne" for every user in the fake profile (DevIdentity has no `/api/v1/auth/consents`).
3. **F-03 Major** The practitioner's name is missing in booking detail ("Programista: Programista"), checkout and confirmation ("· poniedziałek, 23 listopada… · 180,00 zł" starts with a stray dot) and the practitioner's list says only "Klient ·".
4. **G-3 Major** No dark theme although the contract demands one; `color-scheme` is not declared either.
5. **G-4 Major** Touch targets: header links 20 px high at 390 px, wrapping to two rows with no menu; 10 to 26 targets under 44 px on every phone page.
6. **P-LIST-2 Major** The practitioner list says "Wyniki: 6" under an empty result ("Brak programistów dla wybranych filtrów") and shows four identical verification badges on every card; the filters are 22 chips.
7. **P-PROF-1 Major** The profile is a wall of 10 days x 13 time pills with a full-width "Zarezerwuj" button that is not tied to a time; month names are capitalised ("23 Listopada") and the member-since line is ungrammatical ("od listopad 2026").
8. **P-ADM-1 Major** Admin pages show raw ids (booking GUID, `demo-client-2`), tabs glued together ("OtwarteRozstrzygnięte"), no amount on a dispute that asks for a partial refund.
9. **P-OFF-1 Major** "Wyłącz" on an offer is a red button that acts at once: no confirmation, no undo. The audit itself hit it by accident and removed the only offer of a practitioner (see 7).
10. **P-REG-1 Major** Form validation shows one error at a time in a banner above the form (register: the short password is never reported while the consent error is shown) instead of inline messages per field; the terms line prints "(wersja dev-1)".

## 7. Notes on method, mistakes and what is not shown

- **Own mistake, kept honest:** the first version of the inert-button probe clicked buttons on every role's pages with a deny list of names; "Wyłącz" was not on it and it disabled the only offer of `demo-practitioner-3`. I noticed it when the profile had no slots, reseeded (`dotnet run --project tools/Gabinety.DemoSeeder -- --reset`) and reran everything. The probe now runs only on public, read-only pages (visitor: home, list, profile, pricing, login) and found no inert button there. **No inert-button check was done on signed-in pages** (it would write); the buttons on those pages were exercised by the flows instead.
- The audit writes to the fake profile (it registers a user, books, pays, cancels, reviews). It is meant for a throw-away stack.
- The app was served by `next dev` (the AppHost's `web` resource runs the `dev` script). The Next.js dev indicator (a grey square at the top-left of every capture) and the CSP console message are dev-mode artefacts. Layout and mechanical results should hold in production; that was not re-run.
- Dark captures are identical to light ones for the reason in G-3.
- Screenshots are palette-quantised PNGs (64 colours, no dither) at 1x scale; tall pages are cut at 3600 px (1440) / 5200 px (390), flow steps at 3000 / 4200 px.
